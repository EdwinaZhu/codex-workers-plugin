## 状态读取

`scripts/collector.py` 每 2 秒读取一次本地 SQLite 元数据，并探测现有任务写锁。只有轮次正在运行且本机仍持有写锁，才认为任务活跃。归档任务和内部子任务被过滤。

- `state_*.sqlite`：任务 ID、显示名称、项目路径、更新时间和当前记录路径。
- `thread_history_*.sqlite`：轮次 ID、状态、开始和结束时间。
- `thread-writer-locks/`：是否仍有本机持有者。

数据库使用只读连接。字段属于 Codex 内部格式，可能随版本变化。

恢复任务时，数据库可能仍停留在上一轮。`scripts/lifecycle.py` 会跟随当前记录文件，只解析生命周期事件前缀，用较新的开始／完成／中断事件修正状态；其余正文按块跳过。文件替换或截断后重新读取，未写完整的行等待下一次轮询。

## 离场计时

每个任务以 ID 对应一个工人。首次确认活跃时加入，再次确认活跃时更新最后活动时间。完成、暂停、失败或断连后停止续期；到「最后活动时间 + TTL」时离场。

工人名单只保存在内存里，重启后不会恢复旧的空闲工人。读取失败也不能续期。

## 窗口

`native/Workers.swift` 从管道接收快照。所有工人都是同一个透明 `NSPanel` 的子视图，按正方形紧密排列，拖动时移动整个窗口，离场后自动补位。

三张 PNG 分别表示工作、欢呼和睡眠；完成约 90 秒后切换为睡眠，TTL 到期则离场。审批和失败使用橙／红标记，断连时变淡。窗口位置和尺寸保存在 macOS 偏好设置中。

可选 Hooks 补充工具和审批事件；登录启动由 `scripts/login_startup.py` 管理。详见 [插件](plugin.md) 和 [隐私](privacy.md)。
