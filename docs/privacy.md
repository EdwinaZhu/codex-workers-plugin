# 隐私与数据边界

[返回 README](../README.md)

小队的运行时不包含 HTTP 客户端、监听端口、遥测或模型调用。状态读取、窗口绘制、设置和素材都在本机。这里描述的是小队自身的行为；Codex 应用本身的数据处理不由本项目控制。

## 会读取什么

| 数据源 | 读取目的 |
| --- | --- |
| `~/.codex/state_*.sqlite` | 任务 ID、显示名称、项目路径、更新时间、来源、归档标记和当前记录路径 |
| `~/.codex/thread_history_*.sqlite` | 轮次 ID、状态、开始及结束时间、轮次排序 |
| 现有 `thread-writer-locks` | 检测本机是否仍有任务持有者 |
| 当前 `rollout_path` | 提取顶层生命周期事件的轮次 ID、事件类型与时间 |
| 可选 Hook 标准输入 | 在内存中解析事件对象，仅保存允许的元数据字段 |

SQLite 连接使用 `mode=ro` 和 `query_only`。不会修改 Codex 的数据库或锁文件，也不会读取 `auth.json`。不查询可能含完整首条提示词的旧 `title` 字段。

**读取器会扫描记录文件的字节。** 定位下一行需要从文件读取内容；实现仅匹配生命周期事件前缀，其余部分按块跳过，不 JSON 解码消息、推理、工具参数或结果，也不保留或输出这些正文。不能把这一行为描述为「完全不接触记录文件」。

Hooks 接口传来的 JSON 对象会在内存中被解码，但落盘字段仅为 `session_id`、`turn_id`、`event` 和 `at`。不会输出上下文、决定审批或记录工具参数。是否启用 Hooks 由 Codex 的审阅与信任流程控制。

## 会保存什么

默认目录为 `~/.codex-workers/`：

| 文件 | 内容 |
| --- | --- |
| `settings.json` | TTL 设置 |
| `runtime.json` | 进程号、刷新时间、工人和窗口数量、尺寸、素材加载数量及错误标记 |
| `<session-id>.json`（可选） | Hook 事件元数据 |
| `<session-id>.lock`（可选） | 小队自己的 Hook 写入互斥文件 |

工人名单仅存在于进程内存中。`runtime.json` 不含任务名、任务 ID 或正文。退出后诊断文件可能仍保留，因此查看时需要同时检查刷新时间。

小队位置和格子大小另存于 macOS 的本地偏好设置。开启登录启动会写入 `~/Library/LaunchAgents/local.codex.workers.login.plist`；用户关闭该选项时移除它。

主动点击「复制会话名」会写入系统剪贴板。悬停与详情会显示任务名和项目名；这些信息可能本身就是私人信息。

## 调试与分享

`scripts/collector.py` 的标准输出包含用于展示的任务元数据。它只输出到本地终端或进程管道，**不等于可直接公开的诊断报告**。提交 Issue 时优先描述现象、版本、错误标记和数量，并移除任务名、路径和 ID。

测试在临时目录创建虚构数据库、锁和记录，不需要实际任务内容。仓库预览图也是虚构任务，不是桌面截图。

`CODEX_HOME` 可覆盖 Codex 数据根目录，`CODEX_WORKERS_DATA` 可覆盖小队数据目录。原生进程直接执行时会继承环境变量；通过 Finder 启动不一定继承终端变量。若要保持数据仅在本机，请使用普通本地目录。
