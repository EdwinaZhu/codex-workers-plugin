# Codex Workers · 工人小队

**把同时进行的 Codex 任务，变成桌面上的像素工人。**

开着多个任务时，不必来回切换窗口确认进度：每个活跃的本地任务都会加入小队，工作时低头，完成时欢呼，空闲时睡觉。小工人挤在同一组透明工位里，任务停止活动一段时间后自动离场。

## 特点

- **一个任务，一个工位**：只为检测到正在运行的本地任务创建工人，历史空闲任务不会挤满桌面。
- **紧密排列，整组移动**：默认每格 48 × 48 点，所有工位共用一个悬浮窗口；拖动任意工人即可移动整组。
- **用姿态表达状态**：低头工作、举手欢呼、歪头睡眠，无需常驻文字标签。
- **各自计时，自动补位**：每个工人独立计算离场时间，离场后自动收拢队形。
- **原生 macOS 应用**：Swift / AppKit 窗口、菜单栏入口，可跨桌面显示，也可选择登录时启动。
- **本地运行**：Python 标准库读取本机状态；运行时不联网、不调用模型、不上传数据。

这是一个独立开发的桌面伴侣，并非 OpenAI 官方产品。当前界面为中文。状态适配器依赖 Codex 的内部本地文件格式，尚不是稳定的公开 API。

## 快速开始

需要 **macOS 13 或更高版本**、Xcode Command Line Tools（或 Xcode）、可用的 `/usr/bin/python3`，以及正在使用的 Codex 桌面应用。项目没有第三方运行时依赖。

首次安装编译工具：

```sh
xcode-select --install
```

下载或克隆本仓库，进入仓库根目录后执行：

```sh
bash scripts/build.sh
open "dist/Codex Workers.app"
```

菜单栏出现双人图标即表示小队已启动。在 Codex 中开始一个本地任务，通常下一次轮询（约 2 秒）就会出现工人。首次读取大型历史文件时可能需要更久。

如果已有小队在运行，先从菜单栏退出旧实例，再打开新构建的应用。应用限制为单实例。

### 安装到用户应用目录

先退出正在运行的小队，再从仓库根目录执行：

```sh
mkdir -p "$HOME/Applications"
ditto "dist/Codex Workers.app" "$HOME/Applications/Codex Workers.app"
open "$HOME/Applications/Codex Workers.app"
```

安装后可在菜单中开启「登录时自动启动」。这个选项使用上述固定安装位置；直接运行 `dist/` 下的版本不等于完成安装。

`bash scripts/launch.sh` 是日常启动和插件使用的入口：优先打开 `~/Applications/` 中已安装的版本，否则使用或构建 `dist/` 中的版本。开发时请使用前面的显式构建命令。

## 状态与离场时间

| 状态 | 工人表现 | 行为 |
| --- | --- | --- |
| 正在工作 | 低头看电脑 | 每次确认活跃都会续期 |
| 刚刚完成 | 举手欢呼 | 完成后约 90 秒内显示，TTL 到期会提前离场 |
| 空闲或暂停 | 歪头睡眠，带有 Z | 留在原位，等待 TTL 到期 |
| 有审批请求 | 工作姿态，加橙色标记 | 需要可选 Hooks 的信号 |
| 任务失败 | 工作姿态，加红色标记 | 不续期 |
| 断连或状态未知 | 工作姿态变淡 | 不续期，等待重连或离场 |

**TTL 从最后一次确认活跃时算起**，默认 5 分钟。持续工作的任务不会因为运行时间长而消失。每个任务分别计时；某个任务继续工作，不会替其他任务续期。

完成约 90 秒后会切换为睡眠，直到离场。应用重启后只接入此时活跃的任务，不恢复上次留下的空闲工人。三张 PNG 对应三种静态姿态，随状态切换。

## 操作

| 操作 | 效果 |
| --- | --- |
| 拖动任意工人 | 移动整个小队，工位不能单独分离 |
| 悬停 | 查看任务名称、项目与状态 |
| 点击工人 | 打开详情，可复制任务名或打开 Codex |
| 右键工人 / 点击菜单栏图标 | 调整大小、TTL、显示位置和登录自启 |

每格可选 **40 / 48 / 56 / 64 点**；TTL 可选 **1 / 3 / 5 / 10 / 30 分钟**。通常每行最多 4 人，并根据可用屏幕空间调整。没有工人时保留菜单栏图标。

详情中的「打开 Codex」打开应用；查找具体任务可使用「复制会话名」。

## 工作原理与隐私

应用启动一个本地 Python 子进程，每 2 秒生成一次状态快照，通过管道交给 AppKit 窗口。读取器结合只读 SQLite 元数据、现有任务写锁和当前记录文件中的生命周期事件，判断任务是否活跃，再为每个工人维护独立 TTL。

读取范围包括任务 ID、显示名称、项目路径、轮次状态和时间。为修正数据库更新滞后，读取器会扫描当前记录文件的字节，但只解析生命周期事件前缀，不解析或保留消息正文、工具参数或推理内容。Hooks 输入仅保留允许的事件元数据。凭据文件不在读取范围内。

自身设置和计数诊断保存在 `~/.codex-workers/`，位置和格子大小保存在 macOS 偏好设置。PNG 素材随应用打包，运行时无网络请求、遥测或模型调用。

详细说明见 [架构](docs/architecture.md) 和 [隐私与数据](docs/privacy.md)。

## 可选的 Codex 插件

仓库根目录同时提供 `.codex-plugin/plugin.json`、`skills/workers/` 和 `hooks/hooks.json`，用于从 Codex 中启动、诊断小队，或补充工具调用及审批事件。

**单独编译并运行应用即可使用基本功能，无需安装插件或启用 Hooks。** 下载本仓库也不会自动安装插件。插件接入方式和边界见 [插件说明](docs/plugin.md)。

## 开发

```sh
# Python 状态机和只读适配器测试，使用临时测试数据
/usr/bin/python3 -m unittest discover -s tests -v

# 完整检查：上述测试、构建、签名验证、原生窗口测试
bash scripts/check.sh
```

原生窗口测试需要已登录的 macOS 图形桌面，会短暂显示虚构工人。更多构建、素材预览和发布步骤见 [开发指南](CONTRIBUTING.md)。

## 支持范围

- 覆盖具备 `state_*.sqlite`、`thread_history_*.sqlite` 和写锁的本地 Codex 桌面任务；不覆盖云端任务、远程主机和旧版 CLI 记录格式。
- Codex 更新内部结构后可能需要调整适配器；无法读取时会显示错误，已有工人停止续期。
- 本地构建只包含当前编译机器的 CPU 架构，使用 ad-hoc 签名，未做 Developer ID 签名或公证。
- 目前尚未指定开源许可证。

遇到「任务运行了但没有工人」，请先查看 [常见问题](docs/troubleshooting.md)。
